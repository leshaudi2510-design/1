# Open-source toolkits to arm the studio

Decision document for the owner. Scope: Claude Code toolkits, skills, MCP servers, guides and compliance references for (A) the UK social-casino static-site factory and (B) Google Ads PPC. Everything Claude Code (ECC), claude-swarm and agentshield are already cloned under /home/user/affaan-m and are deliberately not re-evaluated here; agentshield is referenced only as our existing scan gate.

Evidence basis: six scouting sweeps (Claude Code ecosystem, Anthropic-official, Google Ads PPC, SEO/design/deploy, agent-fleet ops, UK gambling compliance) and thirteen deep reads of the strongest candidates, all on 2026-10-06. Numbers (stars, dates, counts) are quoted only where a sweep or deep read actually read them; otherwise the field says "unknown". Nothing was cloned or installed in the scouting phase. A review pass on 2026-10-06 (this revision) did run the two scanners, ccusage and the npm/PyPI/GitHub lookups inside the container, and corrected the rows below accordingly. Dates in the Maintenance column: where a row says `pushed_at`, it is GitHub's last-push date; a bare date was read from GitHub on 2026-10-06 without recording the field and may be `updated_at`, which moves on stars/forks and overstates activity.

One fact changes almost every recommendation below and must be read first:

> **Claude Code on the web (cloud sessions) and Routines do NOT install plugins or marketplaces.** Not from `~/.claude`, not from `enabledPlugins` / `extraKnownMarketplaces` in the repo's `.claude/settings.json`, and `/plugin` is unavailable there. What a cloud session DOES load from the cloned repo: `CLAUDE.md`, `.claude/rules/`, `.claude/skills/`, `.claude/agents/`, `.claude/commands/`, and, in single-repo sessions only, `.claude/settings.json` hooks + permission rules and the repo-root `.mcp.json`. (Official docs: code.claude.com/docs/en/cloud-environments, "What carries over".)

Because our main surface is cloud sessions and routines, "adopt" in this document always means **vendor the specific reviewed files into `/home/user/1/.claude/` and `/home/user/1/.mcp.json` at a recorded commit, scan them, commit them**. Marketplace one-liners are listed for anyone on a desktop terminal, but they are not our distribution path. Today `/home/user/1` has no `.claude/settings.json`, no `.claude/skills`, no `.mcp.json` (only `.claude/worktrees/`), and `/home/user/1/opalquestlounge` has no `.claude` directory, so everything below starts from zero.

## 3. Section B — Google Ads PPC

### B.0 Auth prerequisites (read before anything in this section)

- **Developer token.** The official server made the token optional on 2026-09-09 ("Configure Developer Token (Optional)") and two secondary sources (ppc.land, relevantaudience.com) report Google sunset developer tokens the same day, with API access levels now following the Google Cloud project used for OAuth. Google's own docs page was unreachable from here: **verify on desktop before planning around it.** Older tools (gaarf, Opteo client, ads-policy-monitor) still expect `developer_token` in `google-ads.yaml`.
- **OAuth.** A Google Cloud project with the Google Ads API enabled and an OAuth desktop client; one-time `gcloud auth application-default login --scopes https://www.googleapis.com/auth/adwords,...` on a laptop; keep the resulting ADC JSON / refresh token as an environment secret. **There is no read-only Google Ads scope**: `adwords` is full read/write, so read-only is enforced only by the tool surface and by using a Google user that has **Read-only access on the MCC**.
- **MCC.** `GOOGLE_ADS_LOGIN_CUSTOMER_ID` (manager account) for every call; social-casino client accounts in their own MCC, never alongside real-money gambling clients (one account cannot hold both certificates; MCC-level revocations now poison eligibility).
- **Cloud network.** The Trusted allowlist already includes `*.googleapis.com` and `accounts.google.com`, so `googleads.googleapis.com`, `analyticsdata.googleapis.com`, `searchconsole.googleapis.com`, `oauth2.googleapis.com` are reachable over REST. **gRPC / HTTP/2-only APIs do not pass the proxy** (/root/.ccr/README.md), which rules out the official Python Ads MCP in stdio mode inside cloud sessions and routines.
- **Secrets.** Environment variables are readable by anyone using the environment. On Pro/Max, static bearer keys can be API credentials attached by the proxy; Google's short-lived OAuth access tokens do not fit that model, so the refresh flow runs inside the session with the refresh token as a secret. Never put tokens in SKILL.md, `.mcp.json` (use `${VAR}`) or the repo.

**Immediate value without any API access:** the marketingskills references (RSA spec, Search playbook, audit guardrails, 32-check audit), our `ad-policy-review` skill + Node linter, Lighthouse/Unlighthouse landing-page audits, the Consent Mode v2 Playwright check, Google Ads Scripts generated from the wookstar skill (run inside the Ads UI, no token), and "export mode" audits on pasted CSVs (google-ads-copilot pattern).

**Consent and cookies.** Playwright `consent` section: no third-party request and no non-essential storage before consent; `gtag('consent','default')` with all four signals `denied` precedes any tag load; `update` fires with the chosen state after Accept; Reject and Accept have equal prominence (DOM/CSS assertion); cookie policy page lists every storage item found by the crawl. **WCAG 2.2 honesty.** axe + equal-access cover the DOM-checkable criteria; document the remaining 2.2 criteria as manual checks in COMPLIANCE.md and never claim "WCAG 2.2 AA verified" from engines alone.

**Monitoring cadence.** Monthly routine: WebSearch for "Update to Gambling and Games Policy" and new `support.google.com/adspolicy` answer IDs, diff against `rules/refs/`, open a task on change; quarterly the owner re-captures the full pages from a desktop browser (support.google.com, developers.google.com, asa.org.uk, cap.org.uk, ico.org.uk and web.archive.org are all blocked from the container).
