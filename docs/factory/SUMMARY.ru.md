# Фабрика сайтов: краткое резюме для владельца

Основной документ: `MASTER-PLAN.md`, версия 1.1. В репозитории это `docs/factory/MASTER-PLAN.md`. Это единственный план; три исходных документа и разведка инструментов остаются справочными. В версии 1.1 исправлены все 41 замечания ревью; журнал исправлений находится в разделе 0.1.

## 1. Что такое фабрика
Это один репозиторий, в котором студия массово собирает сайты трёх типов и ведёт для них рекламу Google Ads:
- британские бесплатные социальные казино (эталон: Opal Quest Lounge — 277 автоматических проверок, Lighthouse 99–100);
- сайты онлайн-игр (порталы, отдельная игра, детский вариант);
- маркетинговые сайты отелей с казино.

Работа идёт в Claude Code в облаке:
- отдельная облачная сессия на каждый сайт;
- центральная сессия-координатор («хаб»), которая сливает работу и проверяет её;
- расписания (routines) для мониторинга;
- приватная доска Board (артефакт с общей базой) со статусом всех заказов.

## 2. Архитектура простыми словами
- **`engine/`**: общий движок. Сборка, страницы, проверки, шрифты. В нём нет ничего, что относится к конкретному сайту или типу.
- **`types/<тип>/`**: «пакет типа». Здесь правила конкретного типа:
  - страницы и обязательные тексты (например, дисклеймер казино);
  - проверки соответствия правилам;
  - список ссылок на политики Google, ASA и ICO;
  - шаблон нового сайта;
  - рекламный набор PPC.
- **`sites/<slug>/`**: данные одного сайта. Конфиг, тексты, тема, картинки.
- **`orders/<slug>/`**: заказ. Бриф, `order.json`, вопросы клиенту, предложение, доказательства, PPC-набор.
- **`tools/`**: инструменты фабрики. Проверка заказа, уникальность сайтов, статусы, доска, сканер безопасности.
- **`.claude/`**: слой ИИ. 18 команд, 20 агентов, 8 workflow, 8 хуков. Ещё 13 расписаний описаны в `docs/routines.md`.
- **Гейты.** Сайт уходит в прод только через `/ship`, и только после всех проверок, одобрения и набранной вручную фразы `ship <slug>`.
- **Политики.** Ни одна цитата из политик пока не проверена, потому что из песочницы нельзя открыть официальные сайты. Поэтому:
  - правила на основе цитат выдают только предупреждения;
  - собственные инварианты студии блокируют всегда;
  - запуск блокируется, пока нужные записи не подтверждены человеком.

## 4. Как обрабатываются три типа сайтов
- **Социальное казино** — полный пакет; его извлекают из нынешнего движка в фазах 1–2.
  - Варианты: свои игры (можно рекламировать) и демо-лобби Pragmatic (рекламировать нельзя никогда).
  - Обязательны: дисклеймер, лента 18+, линия торговых марок, блок ответственной игры, GamCare.
- **Онлайн-игры** — заглушка в фазе 1, полный пакет в фазе 4.
  - Игры встраиваются через iframe провайдеров (GameDistribution, GamePix и т. д.).
  - Любой сторонний фрейм грузится только после явного согласия на cookies.
  - Для каталога обязательны оригинальные редакционные тексты.
  - Детская аудитория определяется только по подписанной оценке.
- **Отель с казино** — заглушка в фазе 1, полный пакет в фазе 4.
  - Режим A: домен без казино, по умолчанию.
  - Режим A+: казино только как удобство, с юристом.
  - Режим B: отдельный домен, после письменного подтверждения Google.
  - Многоязычность, бронирование, галерея, карта.
- Уникальность сайтов проверяется внутри типа. Между типами проверяется только дословное копирование текста.
- У каждого типа свой PPC-набор:
  - конверсии;
  - Consent Mode v2 (basic);
  - гео-списки;
  - гигиена аккаунта;
  - для казино ещё и досье на сертификацию.

## 8. Действие по сети (одно, для вас)
В Claude Code в облаке откройте меню облачного окружения в заголовке сессии, затем **Edit → Network access**. Выберите **Custom**, оставьте список пакетных менеджеров по умолчанию и добавьте в **Allowed domains**:
- `github.com`
- `raw.githubusercontent.com`
- `codeload.github.com`
- `support.google.com`
- `developers.google.com`
- `www.asa.org.uk`
- `www.cap.org.uk`
- `ico.org.uk`
- `www.gamblingcommission.gov.uk`
- `www.legislation.gov.uk`

Инструкция: https://code.claude.com/docs/en/cloud-environments#network-access

Есть альтернатива без расширения сети. Сохраните с компьютера страницы политик как HTML в `docs/policy-watch/refs/`, затем подтвердите их командой `/policy-recheck --initial <имя>`.

Пока сеть не открыта, фаза 1 всё равно идёт. Не подтверждены только цитаты политик, а значит, никакой запуск невозможен.
